- Cryptography is something to transform a message in secure form so that no unauthorized can access or read the message. This encoded message is called cipher text.
- During this process we are generally ciphering the text or encoding the text.
- Text to Cipher is Encryption and the process used is known as the encryption algorithm.
- Since the message can also be decrypted using the same algorithm it poses an issue, that's why there's something called the ==key==. Plain text and key is used to convert the text into cipher text.
- To convert the cipher text into plain text the other side would need the key.
- There are two types of encryption algorithms:
    - Symmetric algorithm: same key to convert from text to cipher and vice versa
        - Example: DES (Data Encryption Standard), Triple DES, AES
    - Asymmetric algorithm : It has two keys. One key for encryption and second key for decryption. No single key can be used to achieve both.
        - Example: RSA
- The bigger the size of the key the stronger is the algorithm.

### **Why not use Asymmetric algorithm for everything ?**

- Resources required to handle asymmetric encryption, slower to decrypt and encrypt. CPU usage is really high.
- The third type of cryptographic algorithm is Hashing algorithm.
    - Hashing algorithms are one way algorithm, encrypt and you cannot decrypt it.
    - Technically hashing is not actually encrypting data. The result of hashing algorithm is called ==**digest** or **digital fingerprint** or a **hash file.**==
    - While encryption algorithm ensures confidentiality and integrity due to the encoding that they provide. Hashing algorithm only ensures integrity meaning the message has not been changed or tampered.
    - Example: MD5, SHA, SHA2, RIPEMD
    - One of the primary usage of hashing algorithms is HMAC or Hashed Message Authentication Code
        - Used for authentication
        - Suppose Alice and Bob want to exchange a message and both have a symmetric secret key.
        - Now Alice encrypts the message with the shared key and hashes the encrypted message+key with a hashing algorithm.
        - Alice then sends over the encrypted file with the generated hash
        - Now on Bobs end when he recieves the message and the digest he first runs the hashing algorithm with the key to generate the hash. Then compares the hash file with the one recieved from Alice if they are same it means the message is indeed from Alice. And then the encryption algorithm with the key can be used to decrypt the message.
        - The primary use of HMAC is SSL Protocol.
